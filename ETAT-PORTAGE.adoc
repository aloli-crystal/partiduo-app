== Lot P — ce qui existe (26 septembre 2026)

* Projet Marten (Marten 0.7 en `path:`), branche `development`, licence
  AGPL v3, `shard.yml` en `path:` + `shard.override.yml`.
* Applications : `modules`, `auth` (modèle `User` + migration), `core`,
  `cards`, `vat` (`be/`, `fr/`), `accounting`, `invoicing`, `analytic` —
  chacune avec son manifeste et ses traductions fr/en/nl.
* Registre `Partiduo::Modules` (squelette) : manifeste (`code`, `name`,
  `version`, `requires_core`, `kind`, `depends_on`, `depends_on_any`,
  `permission`, `menu`, `ui`, `on`), activation par `PARTIDUO_MODULES`,
  contrôle au démarrage ; événements `Partiduo::Events` (liste fermée,
  synchrones, pièces actives seulement).
* Contrat `Partiduo::Api` : `Actor`, `Guard`, `Result`, `FieldError`,
  `Transaction`, `ModuleDisabled` / `Forbidden` / `NotFound` ; exemples
  `Api::Core.instance` et `Api::Accounting.check_entry`.
* Specs : 37 exemples (registre, contrat, transaction, garde-fou, isolation
  des modules, complétude des traductions, en-têtes SPDX, connexion PostgreSQL).
* CI GitHub Actions : format, Ameba, garde-fou, specs × 3 configurations
  (non exécutée sur GitHub, voir BLOCAGES B-002).

== Lot P — partiduo-ui-bulma (26 septembre 2026)

* Application Marten `ui` (`PartiduoUi`) qui compose le cœur (`require
  "partiduo"`) : page d'accueil (gabarit `base.html` repris de la maquette),
  libellés fr/en/nl, route `ServeAsset` en développement et en test.
* Fichiers statiques versionnés (D-015) : Bulma 1.0.4, HTMX 2.0.11,
  `theme.css` de la maquette, IBM Plex auto-hébergée, planche d'icônes Lucide.
* Opal sans npm ni Node (D-013) : `opal/demo.rb` compilé par la gem `opal`
  en `src/ui/assets/ui/js/opal/demo.js`, empreinte des sources vérifiée par
  spec, exécution vérifiée sous JavaScriptCore.
* Garde-fou ADR-005 D3 côté interface (D-014) : `scripts/api_boundary.cr`,
  seul `Partiduo::Api` plus la composition est admis.
* CI GitHub Actions : format, Ameba, garde-fou, Opal `--check`, specs.
* Specs : 27 exemples.

== Lot 0 — ce qui existe (27 septembre 2026)

Cœur (`partiduo-app`) :

* Registre `Partiduo::Modules` étoffé : activation enregistrée en base
  (`modules_activation`, `PARTIDUO_MODULES` en valeur initiale, D-018), menus
  déclarés par les manifestes (D-019), catalogue de permissions avec libellés
  i18n (D-020), événements à charge utile contrôlée émis après validation de
  la transaction (D-021) ; contrat `Partiduo::Api::Modules`
  (link:doc/api/modules.adoc[]).
* `Core::Settings` : identité de la société, régime (be/fr) immuable,
  contrôle des identifiants (numéros de TVA BE/FR, D-SET-003), politique
  d'authentification ; jeu de données initial `Partiduo::Api::InitialData` ;
  correctif de lecture des `numeric` (B-SET-001, D-SET-008)
  (link:doc/api/core-settings.adoc[]).
* Authentification et droits (`auth`) : mots de passe (password-policy,
  BCrypt), TOTP avec anti-rejeu, passkeys WebAuthn, fédération SAML/OIDC au
  niveau du contrat, niveaux de session et élévation, sessions tenues par le
  cœur, limitation des tentatives, profils et permissions, droits par
  journal, audit, invitations ; contrat `Partiduo::Api::Auth` (connexion, compte,
  administration) (link:doc/api/auth.adoc[]).
* i18n fr/en/nl de toutes les applications, complétude vérifiée par spec.
* `bin/partiduo-provision` (base, migrations, société, données initiales,
  fichiers de service) et `deploy/bin/partiduo-fleet` (parc : montée de
  version progressive, sauvegardes, retour arrière) (D-SET-006, D-SET-007).
* Specs : 207 exemples (Comptabilité seule : 207 ; Facturation seule : 204
  + 1 en attente ; les deux : 207).

Interface (`partiduo-ui-bulma`) :

* Connexion (mot de passe, second facteur TOTP ou passkey, élévation),
  récupération (lien de remise à zéro, déblocage, invitation), écran
  « Sécurité du compte » (enrôlement TOTP en HTMX, passkeys, codes de
  récupération), tableau de bord, recherche, « À propos », pages d'erreur ;
  menus et routes des extensions par point d'entrée unique (D-UI-003) ;
  trois tailles d'écran (D-UI-014). Décisions D-UI-001 à D-UI-014.
* Specs : 80 exemples (dont accessibilité et extension factice).

== Commandes

[source,sh]
----
cd prod-crystal/partiduo/partiduo-app
SKIP_MARTEN_CLI_PRECOMPILATION=1 shards install
createdb --encoding=UTF8 partiduo_dev
crystal run manage.cr -- migrate                   # base de développement
createdb --encoding=UTF8 partiduo_test             # une fois
crystal spec                                       # base partiduo_test
DATABASE_URL='postgres:///partiduo_test_<agent>?host=/tmp' scripts/specs-modules.sh
crystal tool format src spec && ameba
crystal run scripts/interface_boundary.cr -- src   # garde-fou ADR-005 D3
bin/partiduo-provision --help                      # création d'une instance
----

cd prod-crystal/partiduo/partiduo-ui-bulma
