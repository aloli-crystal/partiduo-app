== Vérification du jalon P + 0 + 1 (27 septembre 2026)

Parcours de bout en bout sur deux instances neuves provisionnées par
`bin/partiduo-provision`, l'une en régime FR avec SKEL dès la création,
l'autre en régime BE où SKEL est activée ensuite par l'administrateur.

Ce qui marche (vérifié) :

* `bin/partiduo-provision` crée base, migrations (cœur, interface, SKEL),
  société, jeux de données initiaux et fichiers de service : plan comptable
  FR de NOALYSS (`mod2`, 163 comptes) et BE (`mod1`, 504 comptes, sans les
  comptes des fiches d'exemple), taux de TVA (14 FR, 8 BE), catégories de
  fiches, journaux A01, V01, F01, O01, profils ADMIN et ACCOUNTANT,
  administrateur invité.
* Enrôlement : invitation (lien affiché par `provision`, D-J1-001), session
  d'enrôlement, mot de passe choisi, invitation à usage unique, connexion,
  tableau de bord.
* Interface : plan comptable par classe, création d'un compte (parent
  déduit), refus champ par champ ; fiche client créée, listée, recherchée,
  consultée ; exercice de 12 périodes créé et consulté ; journaux listés, journal
  d'achats créé (numérotation `DEM-0001`).
* `Partiduo::Api` avec l'acteur de l'administrateur : plan du régime, compte,
  fiche fournisseur, journal, exercices ; acteur sans droit refusé
  (`Forbidden`).
* SKEL : 404 tant qu'inactive, activation par `Partiduo::Api::Modules.activate`,
  anonyme renvoyé vers `/login`, page servie à l'administrateur et à un profil
  `skel.view`, refusée (403, sans entrée de menu) à un profil sans ce droit,
  `entry.posted` consigné et affiché.

Ce qui ne marchait pas, corrigé :

* L'administrateur d'une instance neuve ne pouvait pas entrer : le jeton
  d'invitation était perdu. `provision` affiche désormais le lien
  (D-J1-001, specs ajoutées).

Limites restantes :

* Serveur HTTP non démarrable dans le bac à sable (B-UI-001, B-J1-001) :
  parcours fait par requêtes HTTP en mémoire à travers la pile de Marten
  (D-J1-003), pas dans un navigateur. Passkeys réelles non essayées (B-AUTH-003).
* `entry.posted` publié par `Partiduo::Events.publish` : aucune écriture
  n'existe avant le lot 2 (D-SKEL-003).
* Une commande lancée sur une instance doit reprendre son `PARTIDUO_MODULES`
  (D-J1-004, amendement proposé).

Specs (bases `partiduo_j1_*_test`, D-J1-002) : `partiduo-app` 356 exemples
(Comptabilité seule), 322 + 5 en attente (Facturation seule), 356 (les deux) ;
`partiduo-ui-bulma` 108 ; `partiduo-skel` 22. Format sans changement, Ameba
sans remarque, garde-fous ADR-005 D3 verts.

=== Démonstration du jalon 1

----
# 1. Ligne de commande de la distribution (cœur + interface + SKEL)
cd prod-crystal/partiduo/partiduo-skel

cd ../partiduo-app

  --database partiduo_j1_fr demo-fr
bin/partiduo-provision --manage "$MANAGE" --name "Demo BE SRL" --regime be \
  --vat BE0417497106 --admin-email admin@demo-be.test \
  --database partiduo_j1_be demo-be

# 3. Parcours de bout en bout (enrôlement, référentiel, SKEL)
cd ../partiduo-skel
PARTIDUO_MODULES=accounting,invoicing,skel \
DATABASE_URL='postgres:///partiduo_j1_fr?host=/tmp' \
  crystal run scripts/demo_jalon1.cr -- --host=demo-fr.partiduo.localhost \

  crystal run scripts/demo_jalon1.cr -- --host=demo-be.partiduo.localhost \

# Second passage : sans --invitation (mot de passe choisi au premier :

# 4. Dans un navigateur, quand l'écoute locale est permise (B-UI-001) :

# puis http://demo-fr.partiduo.localhost:8000/invitation/<jeton> (instance
# neuve) ou /login, /accounting/chart, /cards, /fiscal-years,

# Nettoyage

== Critique de complétude du lot A (A:critique, 28 septembre 2026)

`partiduo-admin`, `partiduo-agent` et `manage instance` relus contre
l'ADR-008 (D1 à D5) et l'ADR-002, en supposant l'administration
compromise : aucun chemin ne doit donner les données comptables d'un
dossier ni faire exécuter une commande arbitraire sur un serveur.

Vérifié sans écart : liste fermée des 14 types (`Protocol::KINDS`, plan
par type, refus du reste) ; aucun shell (programmes lancés par argv,
enveloppes qui valident chaque argument, `sudoers` réduit à deux scripts
root) ; `manage instance` limité à neuf actions, sans SQL libre ni
processus lancé, `status` et `backup-plan` sans donnée comptable (ni nom
déposé des pièces) ; l'administration n'ouvre aucune connexion vers les
serveurs ni vers les bases des dossiers, n'a aucun compte dans les
instances ; cookies sans domaine parent (hôte seul) ; `rp.id` de
l'administration distinct de celui des dossiers ; rôles et niveaux
ADR-002 (passkey du super-admin, niveau 2 sinon, limitation, codes de
récupération) ; hôte et base recalculés depuis le sous-domaine
(D-AFN-004).

Écarts corrigés dans `partiduo-admin` (D-CRA-001 à D-CRA-007) :

* *sauvegarde d'un autre dossier* (bloquant) : une tâche forgée restaurait
  la sauvegarde du dossier B dans le dossier A ou effaçait celles de B ;
  chemins bornés à `<backup-dir>/<sous-domaine>/`, vérifiés avant tout
  geste ;
* *lien d'invitation* (bloquant) : il transitait par l'administration et
  ouvre le compte d'administrateur du dossier ; l'exécutant le remet
  lui-même (`--mail-command`, `--mail-from`), l'administration n'en voit
  que la trace ;
* *arguments* : valeurs d'un recours d'accès jamais prises pour des
  options de `manage instance` ;
* *pièces jointes* : liste bornée au stockage de l'instance (agent et
  enveloppe) ;
* *journal des tâches* : lignes de PostgreSQL qui citent des valeurs
  retirées ;
* *durée légale* revérifiée par le serveur (suppression définitive,
  effacement d'une archive) ;
* `Approvals.reject` conditionnel (reste de D-AFN-011).

Vérifications : `partiduo-admin` (base `partiduo_test_critique_a`, ordre
aléatoire) : 139 exemples verts (dont `spec/agent/critique_spec.cr` et
`spec/admin/critique_spec.cr`), format et Ameba sans remarque.
`partiduo-app` : documentation seule (`doc/api/instance-cli.adoc`).

Reste (BLOCAGES) : le serveur voit les données par construction
(B-CRA-001, chiffrement des sauvegardes proposé) ; double validation
déclarative pour l'exécutant (B-CRA-002, signature proposée) ; remise par
un vrai MTA et cloisonnement du compte de l'administration à essayer sur
le premier serveur (B-CRA-003).
