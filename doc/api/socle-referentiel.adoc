= Référentiel du socle : fiches, TVA, exercices, devises, pièces jointes
:toc: left
:toc-title: Table des matières
:toclevels: 3
:icons: font
:source-language: crystal

Référence du référentiel du *socle* (lot 1, ADR-006 D1) : tiers, articles et
services (`Partiduo::Api::Cards`), taux de TVA (`Partiduo::Api::Vat`),
exercices et périodes, devises, pièces jointes (`Partiduo::Api::Core`). Le
socle ne cite aucun module : le rattachement d'une fiche, d'une catégorie ou
d'un taux à un compte comptable appartient à la Comptabilité
(link:accounting-reference.adoc[], D-ACC-001).

Conventions communes : acteur en premier argument, droits vérifiés en tête,
commandes en transaction renvoyant `Result(T)`, erreurs par champ en clés
i18n (fr, en, nl), objets de vue immuables (convention C2 de
`DECISIONS.adoc`). Les décisions de ce périmètre sont `D-REF-001` à
`D-REF-014`.

== Fiches (`Partiduo::Api::Cards`)

Successeur de `fiche`, `fiche_detail` (EAV), `fiche_def`, `jnt_fic_attr` et
`attr_def` (ADR-001 D3). Colonnes typées pour les attributs universels et les
champs de facturation française du cœur (ADR-004 D5) ; `extra` (jsonb, index
GIN `jsonb_path_ops`) pour les attributs propres de la catégorie, validés
selon sa définition.

=== Catégories

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`categories(actor, kind = nil) : Array(CategoryView)`
|`cards.card.read`
|Catégories, par nom ; d'une nature si `kind`.

|`category(actor, id)`, `category_by_code(actor, code)`
|`cards.card.read`
|Une catégorie (`NotFound`), ou par code stable (`nil`).

|`check_category(actor, CategoryInput, id = nil) : Result(Nil)`
|`cards.category.manage`
|Contrôle instantané.

|`create_category`, `update_category(actor, id, input)`
|`cards.category.manage`
|La saisie décrit la catégorie *entière*, attributs compris ; un attribut
retiré est effacé des fiches.

|`delete_category(actor, id) : Result(Nil)`
|`cards.category.manage`
|Refusée si la catégorie a des fiches (`base.has_cards`).

|`load_default_categories(Actor.system, locale) : Array(String)`
|acteur système
|Jeu de données initial (chargeur `CARDS.categories`, ordre 12).
|===

* `code` : identifiant stable (`CUSTOMER`, `SUPPLIER`, `BANK`, `SALE`,
  `PURCHASE`, `EXPENSE`, `EMPLOYEE`, `CONTACT`, `TAX_AUTHORITY`), en
  majuscules, immuable ; c'est par lui qu'un module rattache ses paramètres.
* `kind` : `customer`, `supplier`, `item` (articles et services), `bank`,
  `employee`, `contact`, `other` ; immuable dès que la catégorie a des fiches.
* Attributs propres (`AttributeInput`) : `key` (`[a-z][a-z0-9_]*`), `label`,
  `value_type` — `text` (`max_length`, 255 par défaut), `number` (`decimals`,
  4 par défaut, valeur stockée *en chaîne* décimale), `date` (`AAAA-MM-JJ`),
  `boolean`, `card` (identifiant d'une autre fiche) —, `required`.

=== Fiches

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`cards(actor, CardQuery) : Array(CardView)`, `count_cards`
|`cards.card.read`
|Recherche : `search` (nom, quick code, TVA, SIREN, SIRET, description),
`category_id`, `kind`, `enabled` (`true` par défaut, `nil` = toutes),
`extra` (inclusion jsonb, servie par l'index GIN), `limit`, `offset`.

|`card(actor, id)`, `card_by_code(actor, code)`
|`cards.card.read`
|Une fiche ; par quick code saisi librement (`Fiche::get_by_qcode`).

|`check_card(actor, CardInput, id = nil) : Result(Nil)`
|`cards.card.write`
|Contrôle instantané.

|`create_card`, `update_card(actor, id, input) : Result(CardView)`
|`cards.card.write`
|Publie `card.saved` (`card_id`).

|`create_individual_customer(actor, IndividualCustomerInput) : Result(CardView)`
|`cards.card.write`
|Saisie express d'un particulier depuis une facture (ADR-004 D9 révisé) : nom, adresse, courriel facultatif ; catégorie `CUSTOMER` (à défaut la première catégorie de clients), nature `individual` ; sans catégorie de clients : `category_id.no_customer_category` (D-CPY-004).

|`set_card_enabled(actor, id, enabled)`
|`cards.card.write`
|`f_enable` ; publie `card.saved`.

|`card_in_use?(actor, id) : Bool`, `delete_card(actor, id) : Result(Nil)`
|`cards.card.read` / `write`
|`Fiche::is_used` / `remove` : refus (`base.in_use`) si une autre fiche la
cite (attribut `card`) ou si une ligne d'un module la référence.

|`format_code(code) : String`
|—
|Format d'un quick code (`comptaproc.format_quickcode`).
|===

`CardInput` décrit la fiche entière, sauf `code` : `nil` ou vide *génère* le
quick code à la création (six premiers caractères du nom formaté, ou `CRD`,
puis `1`, `2`… en cas de doublon) et le *conserve* à la modification ; un code
saisi déjà pris est refusé.

[cols="1,3",options="header"]
|===
|Champ |Règle

|`name` |obligatoire, 255 caractères
|`vat_number` |compacté ; contrôle FR et BE, forme générique UE sinon ; FR : cohérent avec le SIREN
|`siren`, `siret` |clé de Luhn (exception La Poste) ; SIREN déduit du SIRET ; SIRET commençant par le SIREN
|`routing_id` |code de routage de l'annuaire (`[A-Za-z0-9._-]`, 100 car.), exige un SIREN ; `CardView#electronic_address` = `SIREN[_SIRET[_CODE]]`
|`customer_nature` |client seulement : `individual`, `business`, `public` (`CUSTOMER_NATURES`), vide si pas précisée (fiches créées depuis la migration cards 0003, qui a initialisé les fiches existantes, D-CPY-002) ; `nil` à la saisie garde la valeur ; `Cards.propose_nature(siren, vat_number)` et `CardView#proposed_nature` proposent (SIREN public : premier chiffre 1 ou 2), `#effective_nature` retient (ADR-004 D9, D-FIN-001)
|`pdf_copy` |client : accepte la copie PDF des factures transmises par la plateforme (oui par défaut ; `nil` garde la valeur) — ADR-004 D9, D-FIN-002
|`iban`, `bic` |ISO 13616 (clé modulo 97), ISO 9362
|`address`, `delivery_addresses` |adresse principale et adresses de livraison (20 au plus, la première par défaut) ; pays ISO 3166-1, celui de la société si vide
|`unit_code` |articles : recommandation UN/ECE n° 20 (`Api::Cards::UNITS`, libellés `cards.units.<code>`), `C62` par défaut
|`sale_price`, `purchase_price` |articles : décimaux ≥ 0, quatre décimales au plus
|`vat_rate_id` |articles : taux de TVA par défaut, existant et actif
|`extra` |attributs propres de la catégorie ; clé inconnue refusée
|===

Les champs d'article sont refusés sur un tiers, les identifiants de tiers et
les adresses de livraison sur un article (`not_applicable`). Une fiche change
de catégorie sans changer de nature.

== Taux de TVA (`Partiduo::Api::Vat`)

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`rates(actor, include_disabled = false)`, `rate(actor, id)`, `rate_by_code(actor, code)`
|`vat.rate.read`
|Lecture.

|`check_rate`, `create_rate`, `update_rate(actor, id, input)`, `delete_rate`
|`vat.rate.write`
|Règles de `Tva_Rate_MTable::check` ; le taux ou le code d'un taux cité ne
change plus (`rate.in_use`) : on crée un taux et on désactive l'ancien.

|`load_rates(Actor.system, regime, locale)`
|acteur système
|Taux en vigueur du régime (`Vat::Be::RATES`, `Vat::Fr::RATES`), chargeur
`VAT.rates`, ordre 8.
|===

`RateView` : `code` (cinq caractères, au moins une lettre), `label` (unique),
`rate` en *pourcentage* (`20.0000`), `category` UNCL5305 (`S`, `Z`, `E`, `AE`,
`K`, `G`, `O`, `L`, `M`), `exemption_code` (VATEX) ou `exemption_reason`
(obligatoires pour `E`, `AE`, `K`, `G`, `O`), `reverse_charge`
(autoliquidation), `sale_on_payment` / `purchase_on_payment` (exigibilité à
l'encaissement), `enabled`. Aides : `fraction`, `tax_on(base, decimals = 2)`.

== Exercices et périodes (`Partiduo::Api::Core`)

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`fiscal_years`, `fiscal_year(id)`, `periods(fiscal_year_id?, open_only)`, `period(id)`
|authentifié
|Lecture ; périodes dans l'ordre chronologique.

|`period_for(actor, day) : PeriodView?`
|authentifié
|`find_periode`.

|`current_period(actor, today) : PeriodView?`
|authentifié
|Période du jour, sinon dernière période ouverte commencée, sinon première
période ouverte.

|`check_fiscal_year`, `create_fiscal_year(actor, FiscalYearInput)`
|`core.fiscal_year.write`
|`insert_exercice` : `year`, `start_year`, `start_month`, `months` (1 à 60),
`label`, `opening_period` / `closing_period` (périodes d'un jour).

|`add_period(actor, PeriodInput)`, `delete_period`, `delete_fiscal_year`
|`core.fiscal_year.write`
|Sans chevauchement ; suppression refusée si close ou citée.

|`close_period`, `close_fiscal_year`
|`core.period.close`
|Publie `period.closed` (`period_id`) pour chaque période close.

|`reopen_period`
|`core.period.reopen`
|Refusée si l'exercice est clos.
|===

En base : bornes ordonnées, contrainte d'exclusion `core_period_no_overlap`
(aucun chevauchement, quel que soit le code qui écrit), déclencheur
`core_period_guard` (période close intouchable, exercice clos sans ajout ni
réouverture), fonction `core_period_for(date)` pour les contrôles des modules.
L'état par journal (`jrn_periode`) relève de la Comptabilité.

== Pièces jointes (`Partiduo::Api::Core`, ADR-006 D1)

[cols="2,1,3",options="header"]
|===
|Appel |Droit |Rôle

|`store_attachment(actor, AttachmentInput(filename, content_type, io))`
|`core.attachment.write`
|Types admis (`Partiduo::Core::Attachments::TYPES` : PDF, PNG, JPEG, WebP,
HEIC, TIFF, XML, texte, CSV, documents ODT et DOCX), signature du contenu
contrôlée, 20 Mio au plus, empreinte SHA-256. ODT
(`application/vnd.oasis.opendocument.text`) : archive ZIP (`PK\x03\x04`)
dont la première entrée est `mimetype`, non compressée, de valeur exacte ce
type. DOCX
(`application/vnd.openxmlformats-officedocument.wordprocessingml.document`) :
archive ZIP lisible qui contient `[Content_Types].xml` et `word/document.xml`
(DECISIONS D-HOOK-003).

|`attachment(actor, id)`, `attachment_content(actor, id) : Bytes`
|`core.attachment.read`
|Le contenu est vérifié contre l'empreinte (`AttachmentCorrupted`).

|`delete_attachment(actor, id)`
|`core.attachment.write`
|Refusée tant qu'une ligne d'un module la cite ; fichier effacé après la
validation.
|===

Stockage : `media_files` de Marten, dossier `PARTIDUO_MEDIA_ROOT` (`media` par
défaut). Un module rattache une pièce par une clé étrangère vers
`core_attachment` ; la boîte « Justificatifs à traiter » relève de
l'extension `partiduo-document`.
